# Graftful

Medication and refill tracking for transplant recipients. Local-first, no account,
free. AGPL-3.0.

## Run it

```sh
npm install
npm run dev
```

Open the app and press **Load example regimen** — that fills it with a real
post-transplant regimen so you can see it working before entering your own.

```sh
npm test      # 133 unit tests
npx playwright test  # 14 app + 3 offline
npm run check # types
npm run build # static output in build/, with the offline precache
npm run preview
```

## What works

Four screens. **Today** shows what to take at each time, with pill counts per
product and the derived milligrams. **Stock** shows days of cover per product, with
refill (in boxes) and recount (absolute) as separate actions. **Order** detects when
any product hits its reorder floor, then tops _everything_ up to a shared horizon so
the next pharmacy run is a single trip, and produces the order text. **Setup** holds
products, therapies, the `.ics` reminder export, and JSON backup.

Reminders work through a generated calendar file: no web API can schedule a local
notification, so an `.ics` with `VALARM` entries is the only mechanism that fires
offline, on every platform including iOS, with no server. Push notifications, with a
"taken" button, come in v2.

Everything runs offline after first load, and no health data leaves the device — the
only outbound request the app can make is a cookieless pageview beacon. Both claims are
tested rather than asserted: `e2e/offline.spec.ts` kills the origin outright and reloads,
and `e2e/app.spec.ts` fails if any request leaves the app.

## Layout

```
src/lib/domain/   dependency-free logic; no framework, no browser APIs
src/lib/db/       Dexie schema and repository
src/routes/       Today, Stock, Order, Setup
src/service-worker.ts
static/icons/     vector sources; rasters generated by `npm run icons`
```

`src/lib/domain` deliberately imports nothing. It is the regression baseline for the
project and survives any future UI rewrite.

## The model

Three levels, deliberately separated:

```
Therapy         The morning dose (Alfabine), 14 mg at 07:30
  DoseVersion     14 mg, active from 2016-05-28
    Composition     3 × Alfabine 4 mg
                    1 × Alfabine 2 mg
Product         Alfabine 4 mg capsule   → own stock, own package size
                Alfabine 2 mg capsule   → own stock
                Alfabine 6 mg capsule   → retired, residual stock
```

A dose change is recorded once, at the therapy level, because that is what the
prescriber says: "go to 14." The composition beneath determines which boxes are
consumed and therefore what goes on the pharmacy order. Stock lives on the product,
because that is what the pharmacy dispenses and what runs out. Dose versions are
time-bounded, so changing a dose creates history instead of destroying it.

Units are the primary input and milligrams are derived — never the reverse. A 7 mg
dose from 4 mg capsules would be 1.75 capsules, and capsules do not split.

## Procurement

Products are not reordered independently. One product crossing its floor (`minDays`)
triggers an order, and that order tops **every** product up to a shared horizon
(`targetHorizonDays`), so refill cycles stay aligned.

```
units_needed = ceil((target_days × units_per_day − on_hand − on_order)
                    / package_size) × package_size
```

The useful output is not a row of amber badges but a date: the earliest any product
falls back to its floor, assuming the order arrives in full.

Ordering and receiving are separate events. Ordering records the request and silences
the alert; it does not change stock. Receiving writes a `refill` to the ledger, and
may be short of what was ordered — these products are frequently dispensed
partially, and the remainder stays visible.

## Why the fixture matters

`src/lib/domain/seed.ts` uses **invented product names** — this repository is public,
and a real regimen committed here would publish a complete list of what somebody takes
every day. The _numbers_ are real, taken from the spreadsheet this app replaces. That sheet carried a
hand-maintained "days of cover" column, so every expected figure in the tests is
verified against years of real use rather than invented to make the code pass. It
also contains the awkward cases — two multi-product compositions, a half tablet, a
steroid taper as two dose versions, two retired products, and an as-needed
painkiller with no daily rate.

## Boundaries

The app records clinical data but never acts on it. It does not derive doses,
interpret lab values, warn about interactions, or advise on a missed dose. See
`DECISIONS.md` for the full list and the reasoning — that boundary is what keeps this
outside medical-device regulation, and it is not negotiable feature by feature.

`STACK.md` covers the stack, `COSTS.md` the hosting comparison, `TODO.md` what is
left.
